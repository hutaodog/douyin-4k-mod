## 一、暂停后又自己播放 —— 根因与修复

**根因**：为了帮网页播放器起播，我写了一个每 1.2 秒跑一次的 `nudgePlay()`：

```js
// 旧代码（错）
if (v.paused && v.videoWidth && v.readyState >= 2) v.play();
```

用户点暂停 → 1.2 秒后这个循环看到 `paused === true` → 又 `play()`。**自己跟用户对着干。**

**修复**：每个 `<video>` 只推一次，推过就记标记，之后再也不碰。

```js
if (v.__dy4kNudged) continue;
if (!v.paused) { v.__dy4kNudged = 1; continue; }
if (v.videoWidth && v.readyState >= 2) { v.__dy4kNudged = 1; v.play(); }
```

**验证**：脚本里 `v.pause()` 之后 4 秒仍是 `paused=true, currentTime 不动`。

## 二、原生推荐流（`FeedActivity`）

### 为什么自己做

网页版推荐页在 WebView 里的实测状态：

```
url    = /?recommend=1
video  = 0×0, paused, readyState=0, 元素 rect 628×0     ← 播放器永不初始化
bodySW = 628                                             ← 页面自己按 628 排版
```

从别的路由 SPA 切过去偶尔能出画（1920×1080），冷启动/反复切就不行。继续调 CSS 性价比为 0，于是自己画。

### 结构

```
FeedActivity
├─ SurfaceView + MediaPlayer + HttpMediaSource（带 Referer + Cookie，4K HEVC 硬解）
├─ 数据：dy4kApi.related(seed) → 10 条 → 每条再 dy4kApi.detail(id) 取可播码流
├─ 交互：上下滑切视频 / 单击显隐信息 / 点 💬 拉起评论抽屉 / 返回退出
└─ 浮层：作者头像+昵称、文案、♥💬↗ 数据（底部一排 + 右侧竖排）
```

### 三个关键技术点（都是踩坑踩出来的）

**1. `related` 里的直链不能直接播**

```
从 related 拿的 URL → 原生播放 100ms 后报错 what=1
PC 上带 Referer 测   → 403
```

原因：`related` 返回的 `bit_rate[].play_addr` 是**网页签名**的（URL 里带 `signature=` `tk=webid`），
只信任页面上下文。而 `detail` 接口返回的码流是另一套签名，**原生可以直接播**（`v11-weba.douyinvod.com`）。

所以流程改成：`related` 只用来拿列表 → 每条播放前 `detail` 取真码流。

**2. 播放器的 HTTP 必须带 cookie**

`HttpMediaSource` 之前只带 Referer + UA，`CookieManager.getCookie(cdnUrl)` 返回 null
（cookie 是 `.douyin.com` 的，CDN 域名上没有）。改成取不到就拿 `https://www.douyin.com/` 的 cookie：

```
HttpMediaSource cookie=8930B
probeSize http=206 len=1
feed prepared 3840x2160 dur=2573074     ← 4K 出画
```

**3. 页面回调要按请求 id 匹配，不能用队列顺序**

第一次实现用 FIFO 队列，结果「预取下一条」的响应会被当前视频的回调吃掉，
表现是滑动后卡在「加载视频…」。现在每个请求带 `rid`，页面原样回传：

```java
// WebData
String expr = "(function(){var __r='r7';"
  + "if(!window.dy4kApi){window.dy4kNative.detailData(__r,'{}');return;}"
  + "window.dy4kApi.detail('...').then(function(j){window.dy4kNative.detailData(__r, JSON.stringify(j||{}))});"
  + "})()";
```

同时加了两个兜底：`dy4kApi` 没就绪立刻回调 `null`（调用方重试）、每请求 9 秒超时。

### 顺带做掉的体验细节

| 项 | 处理 |
|---|---|
| 视频播完黑屏 | `setLooping(true)`，单条循环（和手机版一致） |
| 冷启动黑屏等太久 | `WebView` 就绪探测从 `getProgress()>=100` 换成 `!!window.dy4kApi` 求值；重试间隔 600ms |
| 滑动后卡顿 | 播当前视频时**预取**下一条的 detail（缓存进 `detailCache`） |
| 顶部黑边 | `setDecorFitsSystemWindows(false)` + 状态栏透明，视频铺到状态栏下面，只给返回键让出状态栏高度 |
| 点 💬 没反应 | 手势从根容器挪到 `SurfaceView`，浮层/右侧按钮才能收到自己的点击 |
| 回前台不续播 | `onResume()` → `player.resume()` |

### 冷启动实测

```
11:26:34.958  page started      （WebView 开始加载）
11:26:37.356  feed items=10     （+2.4s，related 接口回来）
11:26:38.571  feed prepared 1280x720   （+1.2s，起播）
```

从点图标到出画约 **4 秒**，中间不再经过网页推荐页。

## 三、网页侧本轮改动（保留的部分）

| 改动 | 说明 |
|---|---|
| 暂停不再被打断 | 见第一节 |
| 内容比屏幕宽就等比缩放 | `fitViewport()`：量页面自然宽度 → 改 `<meta viewport>` → `--dy4k-k` 反向补偿我们自己的 UI |
| 站点改 viewport 会被立刻改回来 | `guardViewport()`：`MutationObserver` 盯 `content` 属性 |
| 关注/朋友页去掉左侧竖栏 | `hideSideRail()`（几何特征 + 头像数量判定），随后整页左移补空位 |
| 弹幕只在上半屏、字号 13px | `tidyDanmaku()` |
| 图文页左右切换箭头隐藏 | CSS 一批选择器 |

**仍未解决**：关注/朋友页即使去掉左栏，页面仍按 628 排版，右侧还留一条黑带；
彻底解决要么把它也原生化，要么找到它算宽度的入口。

## 四、复现

```powershell
cd F:\ddddddd\douyin-4k-mod
npm run app:install          # 构建 + 安装 + 启动（直接进原生推荐流）
adb -s 7b0137b5 logcat -s dy4k:I | Select-String 'feed prepared'
```

真机操作：
1. 开 App → 直接进原生推荐流（约 4 秒出画）；
2. 上滑 → 下一条；下滑 → 上一条；
3. 单击画面 → 隐藏/显示浮层；
4. 点右侧 💬 → 评论半屏抽屉；点遮罩或「评论」标题关闭；
5. 返回 → 回到网页壳（关注/朋友/我的 仍是网页版，我的走原生主页）。
