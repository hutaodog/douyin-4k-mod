## 一、最重要的一条发现：真正的"推荐流"藏在 SPA 路由里

抖音桌面版把 `/` **在客户端**重定向到 `/jingxuan`（精选），直接访问 `/?recommend=1` 也会被拽回去。
但只要用 `history.pushState + popstate` 触发站内路由，`/?recommend=1` 就会渲染出
**全屏竖向推荐流**（右侧点赞/评论/收藏/分享栏 + 左下作者文案 + 竖滑切视频），和 App 首页几乎一样：

```js
history.pushState({}, '', '/?recommend=1');
window.dispatchEvent(new PopStateEvent('popstate', { state: {} }));
```

同一招还能秒切其它页（实测耗时）：

| 目标 | 路由 | 实测 |
|---|---|---|
| 推荐 feed | `/?recommend=1` | 360 ms |
| 关注 | `/follow` | < 300 ms |
| 朋友 | `/friend`（注意是单数，`/friends` 是 404） | < 300 ms |
| 我的 | `/user/self` | 160 ms |

> 之前底部导航用 `location.href` 整页重载 → 3–5 秒；现在是纯 SPA 切页。
> 开屏流程：先加载 `/`（被重定向到 `/jingxuan`）→ 等首屏稳定 → pushState 切到推荐流 → 检查是否出画，没出画重试（最多 3 次）。

## 三、踩到的两个坑（都已修，记录备查）

1. **`[data-e2e*="ai"]` 这类模糊属性选择器会把播放器容器一起干掉** → 详情页黑屏（播放器 `display:none`、video 0×0）。
   现在只允许"文字精确等于 AI / AI抖音 / AI搜索"的匹配。
2. **"隐藏播放器之后的所有兄弟节点"这种焦点模式**（focusStage / hideOffscreenLayers）在抖动的 DOM 上极危险：
   有一半概率把播放器自己的父级隐藏，直接黑屏。已移除。

> 教训：在这种每屏几十个 hash 类名、React 随时重渲染的页面上，**只做加法（注入自己的 UI）比做减法（藏页面的东西）安全得多**。
