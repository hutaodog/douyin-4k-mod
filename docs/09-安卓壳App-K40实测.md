# 09-安卓壳 App 真机实测（Redmi K40）

> 目标：不要用户脚本、不要 root、不要改官方包，做一个**能装、能登录、能出 4K** 的安卓 App。
> 本文是 K40 上的实测记录，含每一步的证据、踩的坑和复现命令。
>
> - 设备：Redmi K40（`M2012K11AC` / alioth / SM8250 / Android 13 / 1080×2400@440dpi）
> - 系统 WebView：`com.google.android.webview 104.0.5112.97`
> - App：`com.dypc4k.douyink4` v1.0.0，约 45 KB，v1/v2/v3 签名
> - 时间：2026-10-24

---

**做成了，而且 4K 是原生硬解出来的：**

```
7697934740980125171  →  原生解码 3840×2160   (HEVC 3902kbps, adapt_lowest_4_1)

```

同一时刻网页侧 HUD 一直显示 `hevc ✗`、实际播放 `1080×1920` —— 这就是为什么必须走原生。

## 一、为什么不是"改包"

`docs/06` 已经证明：重新签名 → 登录时服务端判「当前版本过低」，**在服务端，客户端无解**。
所以这个 App 走的是"自己带一个浏览器壳"：

```
WebView（伪装桌面版 UA）
  + 注入脚本（固定档位 / 改 AB / 类 App 界面）
  + 原生 MediaPlayer（HEVC 硬解播 4K）
```

官方 APK 一个字节没动，登录走网页扫码，风控机制看不到任何异常签名。

---

## 二、第一步就撞墙：WebView 不给 HEVC

App 第一版跑起来后，页面 HUD 直接告诉你答案：

```
1080x1920  超清 4K
fps 6.7  8.60Mbps
ab16  hevc ✗  has2k=1
```

`ab16` 说明 AB 改写命中 16 个键、`has2k=1` 说明 2K/4K 档位已经放出来了，
但 `hevc ✗` 说明**网页层根本不能解 HEVC**。

对照设备能力（App 启动时打日志）：

```
WebView pkg: com.google.android.webview 104.0.5112.97
HEVC decoders(3): OMX.qcom.video.decoder.hevc [video/hevc] hw=true;
                  c2.android.hevc.decoder [video/hevc] hw=false;
                  OMX.google.hevc.decoder [video/hevc] hw=false
```

结论：**硬件能解 HEVC，但 WebView 104 没把能力暴露给网页层**
（Chrome/WebView 是 107 才加上 HEVC 支持）。而 4K 码流只有 HEVC：

```
2160p 3840x2160  adapt_lowest_4_1  h265  1982~4113kbps   ← 4K 只有 h265
1920p 1080x1920  normal_1080_0     h264  2869kbps        ← h264 天花板 1080P
```

所以在 WebView 里做多少次 AB 改写都没用 —— **必须换解码器**。

## 三、第二个坑：4K 直链要 Referer

拿页面自己的 `bit_rate[]` 里的 mp4 直链直接丢给 `MediaPlayer.setDataSource(url)`：

```
MediaPlayer:  currery video type video/avc
NuCachedSource2: source returned error -1, 8 retries left
```

在 PC 上复验同一批链接：

```
HEAD 不带头           → 403
HEAD 带 UA            → 403
HEAD 带 UA + Referer  → 200, Content-Length=119582918
```

**douyinvod 对 4K 直链要求 `Referer: https://www.douyin.com/`**，而 `MediaPlayer` 没法加请求头。

解法：自己写一个 `MediaDataSource`（`HttpMediaSource.java`）：
用 `Range` 分块拉（1 MB/块，24 块滑动缓存），每块都带 `Referer` + 桌面 UA。
MediaPlayer 直接读它，等价于"带头的流式播放"。

改完再测：

```
data source: HttpMediaSource (referer-aware)
video size -> 3840x2160
prepared duration=245201ms size=3840x2160
FIRST FRAME after 115ms
```

## 四、最终架构

```
MainActivity（WebView 壳）
├─ 桌面版 UA：Mozilla/5.0 (Windows NT 10.0 …) Chrome/131
├─ shouldInterceptRequest：自己抓主文档 → 把 <script>dy4k.js</script> 插进 <head>
│                            （保证在页面自己的 JS 之前执行；顺带转发 Cookie/Set-Cookie）
├─ onPageStarted：再兜一次注入（脚本内部 `__DY4K_ON__` 幂等）
├─ 全屏沉浸 / 竖屏 / 常亮 / 返回键（再按一次退出、长按重载）/ HTML5 全屏
└─ addJavascriptInterface(NativeBridge, "dy4kNative")

assets/dy4k.js = mobile-web/douyin-4k.user.js
├─ 第1层 sessionStorage['MANUAL_SWITCH'] = 超清 4K（400ms 心跳）
├─ 第2层 AB 响应改写：has_2k=1、auto_clarity_reselect 等归零、isOpenAutoDefi/isPlayAutoDefi=false
├─ 第3层 界面：隐藏左侧导航/顶栏/引流条、播放器全屏、底部标签栏、隐藏右侧浮层、viewport 改写
├─ 第4层 嗅探 aweme 接口的 bit_rate[]（含 <script id="RENDER_DATA">），按 aweme_id 取最高档 mp4 直链
└─ 视频页右下角出现「原生 2160x3840 HEVC」按钮 → dy4kNative.play4k(url,w,h,title)

PlayerActivity（原生播放器）
└─ MediaPlayer + SurfaceView + HttpMediaSource（带 Referer 的 Range 拉流）
   单击出控制条 / 双击 完整↔铺满 / HUD 显示 实际解码分辨率 + 编码 + 时长 + 位置
```

## 五、复现命令

```powershell
cd F:\ddddddd\douyin-4k-mod

# 1) 构建（无 Gradle：aapt2 → javac → d8 → zipalign → apksigner）
powershell -NoProfile -ExecutionPolicy Bypass -File .\mobile-app\build.ps1

# 2) 装到 K40
adb -s 7b0137b5 install -r -d mobile-app\build\Douyin4K.apk

# 3) 一键真机验收（自动开视频页、抓直链、拉原生播放器、读实际解码分辨率）
node mobile-app/tools/acceptance.mjs --shot

# 4) 单独调试
node mobile-app/tools/device.mjs info
node mobile-app/tools/device.mjs eval "dy4k.state()"
node mobile-app/tools/device.mjs eval "dy4k.gears().best"
node mobile-app/tools/device.mjs log dy4k
```

`device.mjs` 用的是 `adb forward tcp:9222 localabstract:webview_devtools_remote_<pid>`，
因此在电脑上可以直接在手机的 WebView 里执行 JS（CDP），不用装任何手机端调试工具。

## 七、遗留与下一步

| 事项 | 说明 |
|---|---|
| WebView 升级 | 把「Android System WebView」升到 107+ 后，网页内也能直接 4K（原生播放器仍可当兜底） |
| 直链有效期 | douyinvod 签名 URL 几小时过期；过期后回页面刷新再点即可 |
| 播放器功能 | 目前只有 播放/暂停/拖动/完整↔铺满；弹幕、倍速、选集还没做 |
| 4K 片源占比 | 取决于视频本身；页面不给 2160 就只能到 1080/1440（App 会照实显示） |
| 账号态 | 本次验收是未登录状态；登录后 AB 返回可能不同，但 has_2k 强置策略对两种状态都成立 |
| 自启动/常驻 | 没有做；就是个按需打开的浏览壳 |

## 八、一句话总结

> 手机上要 4K，卡的不是"选不选"，而是**谁在解码**。
> 网页层（WebView 104）没有 HEVC → 再怎么改 AB 也只能 1080P；
> 把码流从网页里"捞出来"交给原生硬解，K40 上 2160×3840 立刻就有了。
> 顺带发现的两条硬事实：**4K 直链必须带 `Referer`**、**`<script id="RENDER_DATA">` 里才是完整档位表**。
