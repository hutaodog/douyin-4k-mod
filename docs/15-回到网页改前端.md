# 15-回到网页改前端（viewport 策略修正）

> 上一轮我绕去做了原生 feed。这轮按你的要求回到网页版，只改前端样式 + 屏蔽不用的块。
> 核心是找到之前"适配像屎"的真正原因：**viewport 被我们改坏了**。

---

## 一、根本原因（这次真的定位到了）

抖音桌面页自己下发 `<meta viewport ... initial-scale=0.5>`，也就是：

- 它按 **786 逻辑像素**排版，然后整页缩 **0.5** 显示 → 手机上看到的是一份等比缩小的完整桌面布局，**什么都不缺、不会被裁**。
- 我之前为了"让视频占满屏"，把这个 meta 改成了 `initial-scale=1`（innerWidth 变 393）。结果页面按 **628px 最小宽度**排版，装在 393 的视口里 → 右边被裁、留黑边、播放器算成 0 高度。

用 PC 上 393 宽的 Chromium 一测就清楚了：

```
不去动 viewport：  viewport 786x1688，body.scrollWidth 786   （干净）
强制 scale=1 后：  body.scrollWidth 628，右侧溢出            （就是手机上看到的鬼样子）
```

**结论：viewport 一律不改**，想让我们自己的 UI 保持手机尺寸，用 `--dy4k-k = 1/scale` 反向放大就行（scale 从 `visualViewport.scale` 读，实测 0.5 → k=2）。

## 二、这轮改了什么

| 改动 | 说明 |
|---|---|
| **不再改写 viewport** | App 拦截 HTML 的地方不再替换 meta；脚本里 `guardViewport`/`fitViewport` 都退化成 `syncScale()` |
| **UI 尺寸补偿** | `--dy4k-k = 1/scale`：底部导航、浮层、HUD、评论按钮、原生 4K 按钮全部乘这个系数，屏幕上还是手机版大小 |
| **屏蔽桌面外壳** | `hideDesktopChrome()`：左侧竖排图标栏（精选/推荐/AI/关注…）、顶部搜索头；`hideSideRail()`：关注/朋友页左侧那一大列 |
| **弹幕收进画面** | `fitDanmakuBox()`：算出视频真实画面区域（含 letterbox 黑边的扣除），把弹幕容器裁到"画面内、上 55%"，字号 13px |
| **推荐 = 全屏视频页** | 落地页自动跳到 `/video/<上次看的>`；底部「推荐」也走它 |
| **Tab 用整页跳转** | 视频页和网格页需要不同的 viewport，只有整页加载才能带上正确策略（SPA 切换不行） |
| **暂停不再被打断** | 见上一轮：`nudgePlay` 每条视频只推一次 |

## 四、中途踩的坑（值得记）

**手机锁屏导致的误判**：`adb screencap` 出来全是纯黑 15580 字节的图、`document.querySelectorAll('video')` 返回空，
我一度以为是把播放器改坏了，来回改了三轮。其实 `dumpsys power` 显示 `mWakefulness=Asleep`（锁屏了）。

> 以后设备测试第一步：`adb shell dumpsys power | findstr mWakefulness`，不是 `Awake` 就先
> `input keyevent KEYCODE_WAKEUP` + 上滑解锁。

**也不要靠"删掉自己的 CSS 看会不会好"下结论**：在 PC Chromium 里同一份 CSS 完全正常（`bisect-css.mjs` 验证过），
设备上的异常其实是锁屏/后台导致的播放器销毁。

## 五、还没做完的

   下一轮直接对 `video` 元素和它最近的定位祖先下手（`object-fit:cover` + 100vw），或者干脆把关注页也当成视频页处理。
2. **朋友页的模糊背景**（视频两侧的色块）要不要去掉，看你要不要。
3. 顶部状态栏：现在是网页在状态栏下面画，App 侧仍然显示状态栏（你之前要求显示）。
