# PC 补丁 v1.5 定稿：真正把视频换到最高档

> 目标：抖音 PC 客户端每条视频都播它「接口能给到的最高分辨率」。
> 结论先行：**v1.5 达到了**。批量 12 条，12/12 命中接口最高档，其中 7 条真 4K（3840×2160），`err=0`、`giveup=0`。

---

## 一、为什么 v1.3 会「看起来切了、其实没换流」

v1.3 的链路是「让客户端自己切」：往 `player.config.definition.list` 里补一个 4K 条目，再调
`player.changeDefinition(entry, player.curDefinition)`。

反编译 `app.asar` 里的 `/pages/player/index.720d2ebe7aef88f0.js`（744,013 B，xgplayer 本体）后能看到三处致命细节：

### 1. `src` setter 在 MSE 媒体上直接 return

```js
set: function (e) {
  if (!!this.media) {
    ...
    if (es.isMSE(this.media)) { this.onWaiting(); return }   // ← 这里
    this._detachSourceEvents(this.media),
      "Array" === es.typeOf(e)
        ? this._attachSourceEvents(this.media, e)
        : e ? this.media.src = e : this.media.removeAttribute("src"),
      this.load()
  }
}
```

`es.isMSE` 的判定是 `blob:` 前缀：

```js
es.isMSE = function (e) {
  return e.media && (e = e.media),
    !!(e && e instanceof HTMLMediaElement) &&
    (/^blob/.test(e.currentSrc) || /^blob/.test(e.src))
}
```

抖音主播放器平时就是 MSE（`mediaSrc` 是 `blob:https://www.douyin.com/<uuid>`），
所以 `player.src = url` 这一句**什么都没做就返回了**。

### 2. `changeDefinition` → `switchURL` 的 Promise 没有 `.catch`

```js
changeDefinition: function (e, t) {
  ...
  var i = this.switchURL(e.url, U({ seamless: ... }, e));
  i && i.then ? i.then(function () { n.emit(tu, { from: t, to: e }) }) : this.emit(tu, {...})
}
```

失败时既不 emit `after_definition_change`，也不报错——**全静默**。
日志里 `revert` 打了、`curDefinition` 也变成目标值了，但 `<video>` 的 `videoWidth/Height` 一动没动，就是这个原因。

更迷惑的是 `switchURL` 返回的 Promise **3 毫秒就 resolve**：

```
switchURL call def=undefined urlType=[object Array] n=3 hasStart=true
RESOLVED def=undefined now=1920x1080
```

那是旧流触发的 `canplay`，新源根本还没开始加载。

### 3. `_attachSourceEvents` 有竞态

```js
_attachSourceEvents: function (e, t) {
  e.removeAttribute("src"), e.load(),
    t.forEach(function (e, t) {
      n.media.appendChild(es.createDom("source", "", {
        src: "".concat(e.src), type: "".concat(e.type || ""), "data-index": t + 1
      }))
    })
  ...
}
```

先 `removeAttribute("src")` + `load()`，**之后**才 appendChild `<source>`。
`load()` 那一刻媒体没有源，浏览器会立即触发一次 `canplay`/`error`，把等待中的 Promise 提前结算掉。

### 4. 顺带证伪的两条旧假设

- 「我们合成的档位条目 `url` 形状不对」→ **错**。原生条目的 `url` 也是三元素数组
  （`[{"src":"https://v26-web-prime.douyinvod.com/video/..."}]`），`p.config.url` 同样是数组。
- 「`seamlessSwitch` 是切档入口」→ **在播放器实例/原型上根本不存在**
  （探针 `hasSeamless=undefined`，`protoFns` 只有 `onFullscreenChange` / `switchURL` / `changeDefinition`）。
  它属于网页 bundle 里更上层的那层封装。

## 二、v1.5 的做法：自己换源，不请客户端帮忙

```
清掉 <video> 下全部 <source> 子元素
  → 记下 currentTime / 播放状态
  → media.pause()
  → media.setAttribute('src', <目标档 mp4 直链>); media.load()
  → 监听 loadedmetadata，把 currentTime 写回去
  → media.play()
```

三个要点：

1. **必须先删 `<source>` 子元素**。HTML 规范：`<video>` 一旦有 `<source>` 子元素，
   浏览器就忽略 `media.src` 属性。删干净才能真正换流。
2. 这样能让 `<video>` 从 `blob:`（MSE）退回**渐进式 mp4**。实测日志：
   `hard4k def=-2 wasMSE=true before=576x1024` → `state vw:2160, vh:3840, src=https://v11-weba.douyinvod.com/...`。
3. **要保住播放进度**。`src` setter 里有 `this._currentTime = 0`，`load()` 也会归零；
   不恢复的话每次钉档都把视频打回开头。所以换源前记 `keepAt`，`loadedmetadata` 里写回。

## 三、`fillMissing` 的残留误判（22 条里 15 条中招）

现象：`fillmiss best=-2 ladderBest=-2`，即「表内已经有 4K，不用补」——但实际表内只有 540/720。

根因：我们用 `synthEntry` 合成补进 `p.config.definition.list` 的 4K 条目**会残留到下一条视频**，
下一条视频算 `bestDef` 时把上一条的残留算进去了。

修法：

- 合成条目打 `__dypc4kSynth: 1`；
- `defList(p)` 仍返回全量（`step()` 要能选中它）；
- 新增 `realList(p)` 只返回客户端自己的条目；
- `fillMissing` 的 `bestDef`、`step()` 的「退而取最高档」、qlog 的 `bestDefNow` 全部跳过 `__dypc4kSynth`；
- 再加「已有同 def 条目就不再 push」的去重，避免过滤后 `bestDef` 永远偏低而导致每秒重注入。

## 四、换源静默期

硬换源之后 `<video>` 会有几百毫秒 `videoWidth = 0`。
原来 `step()` 每 30/200/600ms 跑一次，看到 `0x0` 就判「没到位」，连续 `revert` 把重试次数打满，
反而让播放器反复 reset。

v1.5 在 media 元素上挂 `__dypc4kForcePendingUntil = Date.now() + 6000`，
静默期内 `realShort = 0` 直接 return；到位或出画面立即清零。

同理，画质日志的 `[final]` 快照改为取**面积最大的 `<video>`**（`pri3 = (!paused && a>0) ? 1e12 : 0`），
`0x0` 时 2 秒后重采一次，避免把 `0x0` 当结果写进日志。

## 五、清晰度标签：兜了一圈才找对

先后试过三条路：

| 尝试 | 结果 |
|---|---|
| 轮询 DOM 改 `textContent`（尺寸 > 8 过滤） | 抓不到 |
| 读 `document.documentElement.outerHTML` 全量搜 | 106 万字符 **零命中** |
| 写 `player.curDefinition` + emit `UpdateSyncText` | 1080 生效，但控件隐藏时不刷新 |

真正的原因很简单：**控件一直在 DOM 里，只是隐藏时 `getBoundingClientRect()` 宽高为 0**，
所以「尺寸 > 8」这个过滤条件永远不成立。去掉尺寸过滤后立刻命中：

```
domHits: [{"t":"高清 1080P","cls":"item selected"},
          {"t":"...","cls":"clarity-wrapper"},
          {"t":"...","cls":"btn btnV2","x":1338,"y":1028,"w":74,"h":32}]
```

结构是：

```html
<div class="gear">
  <div class="virtual">
    <div class="item selected"><div class="clarity-wrapper"><span>高清 1080P</span></div></div>
    <div class="item">高清 720P</div> ...
  </div>
  <div class="btn btnV2">高清 1080P</div>
</div>
```

v1.5 直接改 `.gear .item.selected` 里的 span 和 `.gear .btnV2` 的文字，
文案由**真实解码尺寸**反推（不是接口标的档位——接口常把 1080 的源标成 4K）：

```
rs = min(videoWidth, videoHeight)
-2 → 超清 4K      (rs >= 2000)
-1 → 超清 2K      (rs >= 1300)
 1 → 高清 1080P   (rs >= 1000)
 2 → 高清 720P    (rs >= 800)
 3 → 标清 540P
```

截图确认（裁右下角 6× 放大）：**「连播 清屏 超清 4K 倍速」**。

## 七、踩坑清单

| 坑 | 教训 |
|---|---|
| `import` 写在 `.js` 里 | 父目录没有 `type:module`，必须 `.mjs` |
| `git show xxx:file` 直接重定向 | PowerShell 写成 UTF-16LE，中文全乱、`node --check` 报错。必须 `\| Out-File -Encoding utf8` |
| `.NET` 文件 API 用相对路径 | 它认进程 CWD（`F:\ddddddd`）不是 PowerShell 的 `cd`，会静默写到别处。**必须传绝对路径** |
| 按注释锚点删代码块 | end 锚点没命中时会一路删到下一个注释，曾把 `installGuard` 整段删掉。删前必须确认锚点命中 + 装前跑 `check-snippet.mjs` |
| `node --check` 通过 ≠ 没坏 | 它只查语法，查不出「引用了已删除的函数」 |
| `.ps1` 里写中文 | 无 BOM 的 UTF-8 .ps1 会被 PowerShell 5.1 按 GBK 解，`` `n ``/`` `t `` 转义都坏。给机器的脚本**写纯 ASCII** |
| `SendKeys` 切视频 | 实测 8~10 次按键只切了 1 条。改为**远程控制通道**：页面轮询 `%APPDATA%\douyin\dypc4k-cmd.txt` |
| `SetForegroundWindow` | 用户正操作别的窗口时会失败（Windows 前台锁）；`PrintWindow` 抓 GPU 合成层会全黑 |
| 抖音启动路径 | `D:\软件\抖音\douyin\douyin.exe`（根目录），不是 `8.8.0\` 下的 `app_shell_updater.exe` |
| `--remote-debugging-port` | 传到进程命令行里了但端口不监听，应用自己接管了启动参数，CDP 走不通 |
