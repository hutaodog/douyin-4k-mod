## 零、三条硬结论（先看这个）

### 1. 签名 `a_bogus` 是**页面 JS 在请求发出前自动追加的**

对照实验（`verify-signature.mjs`，同一批 URL、同一份 cookie）：

| 接口 | Node 侧直接请求（只带 cookie） | 页面内 `fetch` |
|---|---|---|
| `/aweme/v1/web/aweme/detail/` | **403** | 200 / 149,267 B |
| `/aweme/v1/web/aweme/post/` | **403** | 200 / 817,346 B |
| `/aweme/v1/web/aweme/favorite/` | **403** | 200 |
| `/aweme/v1/web/music/aweme/` | **403** | 200 |
| `/aweme/v1/web/mix/aweme/` | **403** | 200 |
| `/aweme/v1/web/aweme/related/` | 200 / 816,821 B | 200 / 807,768 B |
| `/aweme/v1/web/user/profile/other/` | 200 / 10,409 B | 200 / 10,410 B |
| `/aweme/v1/web/comment/list/` | 200 但 **0 字节** | 200 / 63,654 B |

而页面自己发出的请求，URL 上都带着签名：

```
/aweme/v1/web/aweme/detail/     a_bogus=df05gHXLYoWcFdKb8CJq9yel…  verifyFp=verify_mvmjtxdu_nMBw
/aweme/v1/web/aweme/post/       a_bogus=my05hwUjYx5badKSmcJF99Al…  msToken=7gBhTQjZZisMuFEW…  verifyFp=…
/aweme/v1/web/comment/list/     a_bogus=EJ4RhFSEEZmVedKG8KJM9tBl…
```

> **结论**：想免签名拿数据，最省事的做法是**在页面上下文里 `fetch`**（同源、带 cookie、站点自己的 fetch 包装器会补 `a_bogus`）。
> 这也是本 App 里 `window.dy4kApi` 的做法。自己实现 `a_bogus` 属于另一条工程路线（算法会变，不建议）。

### 2. 请求头/凭据的实际要求

| 项 | 必需 | 说明 |
|---|---|---|
| `Cookie` | ✅ | 至少要 `ttwid`、`msToken`、`odin_tt`；登录态还要 `sid_guard`/`sid_tt`/`uid_tt` |
| `User-Agent` | 建议 | 桌面 Chrome UA 最稳（移动 UA 会被导到引流页） |
| `Referer` | 部分接口 | 图片/视频 CDN **必须** `https://www.douyin.com/`，否则 403 |
| `a_bogus` | 多数 `/aweme/v1/web/` 写/读接口 | 页面 JS 生成，随时间变化 |
| `msToken` | 部分（如 `aweme/post`） | 有时在 cookie 里、有时在 query |
| `verifyFp` | 大多数 | URL 参数，同时用于服务端校验 |
| CSRF | 写接口 | `passport_csrf_token` cookie + 请求头，**本轮未实测写接口** |

### 3. 分页只有两种模式

| 模式 | 字段 | 用在哪 |
|---|---|---|
| `cursor` + `has_more` | 评论、搜索、弹幕、合集列表 | `cursor` 是**偏移量**，每次加 `count` |
| `max_cursor` + `has_more` | 用户作品 `aweme/post`、喜欢 `aweme/favorite` | `max_cursor` 是**时间戳**，拿返回里的 `max_cursor` 当下次入参；`0` 表示首页 |

## 三、关键数据结构（字段表）

### 3.1 aweme（视频/图文对象）

来源：`aweme/detail` → `aweme_detail`；`aweme/post` → `aweme_list[]`。

```
aweme_id, desc, create_time, aweme_type, duration, is_top,
author, music, video, statistics, text_extra[], share_url,
video_labels[], image_infos[](图文), chapter_list[], danmaku_control,
collect_stat, comment_gid, anchors[], risk_infos, entertainments…
```

**`video` 里最值钱的是 `bit_rate`（码流档位表）**：

```
video: {
  width, height, duration, ratio, format, is_h265, has_watermark,
  cover / dynamic_cover / origin_cover { url_list[] },
  play_addr      { url_list[], width, height, data_size, uri, file_hash },
  play_addr_265  { … },           // HEVC 专用
  play_addr_h264 { … },           // H.264 专用
  bit_rate: [ {                   // ← 27 档（实测这条视频）
      gear_name: "adapt_lowest_4_1",   // 档位名（4K 叫 adapt_lowest_4_1）
      quality_type: 72,
      bit_rate: 4113000,               // bps
      FPS: 59, is_h265: true, is_bytevc1: 0, HDR_bit: 0,
      format: "mp4" | "dash",
      play_addr: { url_list[], width, height, data_size, file_hash }
  } ]
}
```

> 实测：**4K（3840×2160 / 2160×3840）只有 h265**；`format:"mp4"` 才是可直连的渐进文件，`"dash"` 是分片。
> 另外 `aweme/detail` 在**页面内**调用时 `bit_rate` 是满的（27 档）；如果从外部直连会被 403。

### 3.2 comment（评论）

```
cid, text, aweme_id, create_time, digg_count, user_digged,
user { uid, sec_uid, nickname, avatar_thumb{url_list}, unique_id, custom_verify },
reply_comment[]（二级评论，可能为 null）, reply_comment_total,
reply_id, reply_to_reply_id, label_text/label_type（热评/作者赞过）,
text_extra[]（@/话题）, image_list[]（图片评论）, ip_label, is_hot
```

分页：`cursor`（偏移）+ `has_more` + `total`。

### 3.3 user（用户）

```
sec_uid, uid, nickname, unique_id(抖音号), signature, custom_verify,
avatar_larger/avatar_medium/avatar_thumb { url_list[] },
following_count, follower_count, total_favorited,
aweme_count, favoriting_count, follow_status(0 未关注 / 1 已关注 …),
city, country, ip_location, commerce_user_level, enterprise_verify_reason
```

### 3.4 热榜 item

`data.trending_list[]`：`word`、`hot_value`、`sentence_tag`、`word_cover{url_list}`、`video_count`、`rank`。

## 五、踩坑清单

1. **403 ≠ 没数据，可能是缺签名**：Node 直连 `aweme/detail` 一律 403；换成页面内 `fetch` 就好。判据是看响应体：`{status_code:…, status_msg:"…"}` 里的 msg。
2. **200 也可能是空**：`comment/list` 外部直连返回 `200` + 0 字节，容易误判"没评论"。
3. **`msToken` 两个来源**：cookie 里有，URL 里有时也带；页面包装器会自动补。
4. **`verifyFp` 要跟着 URL 一起带**（页面自己会加），手工拼请求时缺了会被风控。
5. **图/视频 CDN 必须带 Referer**：`p3-pc-sign.douyinpic.com`、`douyinvod.com` 不带就是 403（`ImgLoader`/`HttpMediaSource` 就是为此写的）。
6. **`aweme/post` 的 `max_cursor` 是时间戳**（如 `1792204947000`），不是偏移；`0` = 首页。
7. **写接口（点赞/关注/发评论）未验证**：除 `a_bogus` 外还要 CSRF（`passport_csrf_token`），本轮没有触发写操作，别照抄。
8. **频率**：同一账号短时间高频调用会触发验证（滑块/空数据）。抓取器每次请求间隔 ≥ 200ms，实测未触发。
9. **protobuf 接口**（IM）：`/v1/message/*` 返回 `application/x-protobuf`，得按 ByteDance 的 pb schema 解，不在本轮范围内。

## 六、在 App 里直接用（`window.dy4kApi`）

注入脚本里已经挂了一个薄封装，原生侧通过 `WebData` 调用：

```js
// 页面上下文里执行，自动带登录态 + 站点签名
const B = 'device_platform=webapp&aid=6383&channel=channel_pc_web';
const get = (p) => fetch(p, { credentials: 'include' }).then(r => r.json());

dy4kApi = {
  profile:  (sec) => get(`/aweme/v1/web/user/profile/${sec ? 'other/?sec_user_id=' + encodeURIComponent(sec) : 'self/'}?${B}`),
  posts:    (sec, cursor = 0) => get(`/aweme/v1/web/aweme/post/?sec_user_id=${encodeURIComponent(sec)}&max_cursor=${cursor}&count=24&${B}`),
  detail:   (id) => get(`/aweme/v1/web/aweme/detail/?aweme_id=${id}&${B}`),
  comments: (id, cursor = 0) => get(`/aweme/v1/web/comment/list/?aweme_id=${id}&cursor=${cursor}&count=20&${B}`),
  related:  (id) => get(`/aweme/v1/web/aweme/related/?aweme_id=${id}&count=20&filterGids=0&${B}`),
  hot:      () => get(`/aweme/v1/web/hot/search/list/?detail_list=1&${B}`),
  search:   (kw, offset = 0) => get(`/aweme/v1/web/search/item/?keyword=${encodeURIComponent(kw)}&offset=${offset}&count=10&${B}`),
  danmaku:  (id) => get(`/aweme/v1/web/danmaku/get_v2/?group_id=${id}&format=json&${B}`)
};
```

给 4K 用的选档函数（从 `detail` 的 `bit_rate` 里挑最高可播档）：

```js
function bestMp4(aweme) {
  const list = (aweme?.video?.bit_rate) || [];
  const ok = list
    .filter(b => b?.play_addr?.url_list?.length && String(b.format) === 'mp4')
    .sort((a, b) => (b.play_addr.height || 0) - (a.play_addr.height || 0) ||
                    (b.bit_rate || 0) - (a.bit_rate || 0));
  return ok[0] || null;   // 拿到 url/width/height/gear_name 交给原生播放器
}
```

> 注意：**必须由页面上下文发起**（`dy4kApi` 就是这么放在注入脚本里的），换到 Java/OkHttp 就得自己实现 `a_bogus`。

## 七、边界与未知

| 项 | 状态 |
|---|---|
| 写接口（赞/藏/关注/评论/发布） | **未实测**（需 CSRF，且会污染账号数据） |
| 直播流（FLV/HLS 拉流地址） | 未覆盖（`webcast/` 系列只抓到配置，没抓房间流） |
| IM / 私信 | protobuf，未解 |
| `a_bogus` 算法本身 | **未逆向**（页面 JS 生成，会随版本变化；本轮走"借页面签名"路线） |
| 短链/分享页、小程序、短剧付费 | 未覆盖 |
| 风控阈值（多快会触发验证） | 只观察到"未触发"，没摸到边界 |

需要其中任何一项（尤其 `a_bogus` 算法、直播流、写接口），说一声我继续挖——工具链已经齐了（抓取/重放/结构提取），换场景就能跑。
