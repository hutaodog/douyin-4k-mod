# 手机端移植可行性：能不能"界面用手机版、底层用电脑版那一套"

> 结论先行：**没有"完美移植"**。你要的三件事——① 手机 App 原生 UI ② 官方登录正常 ③ 4K 固定——
> 三者最多同时满足两个。下面是精确的取舍与做法。

---

## 一、为什么不能直接搬

| | 电脑端（已跑通） | 手机端 |
|---|---|---|
| 界面 | 远程网页 `www.douyin.com` | 原生 Java/Kotlin + Lynx |
| 播放器 | `xgplayer`（JS） | `TTVideoEngine`（`libttvesdk.so` + Java 包装 `SimKitService`） |
| 清晰度记忆 | `sessionStorage['MANUAL_SWITCH']` | Keva `video_quality_keva/video_quality_type` + `X.0FWR` 枚举 |
| 自动降档开关 | 服务端 AB → 网页 `/service/2/abtest_config/` | 服务端 AB → `PlayerSettingCenter` 的 `not_adjust_after_manually` 等 |
| 我们的注入点 | `preload.js`（网页层，天然存在） | **没有等价注入点**，除非 root |

**能移植的是"思路"**：找到那个"决定降档的开关"，在它生效前改掉。
**不能移植的是"代码"**：手机端没有 JS 播放器，也没有 `preload.js`。

---

## 二、为什么手机改包登录必失败（复述，避免再踩）

登录时客户端上报 `metasec` 生成的设备/客户端指纹；包名可以改回官方，但**签名改不了**（我们自己签的 key）。
服务端比对不上已知客户端 → 判「当前版本过低」。这个判定在**服务端**，客户端改代码绕不过。

**推论：只要 APK 被重新签名，账号功能就废。**
所以要保住登录，只有两条路：**不改 APK（root 运行时 hook）** 或 **不装 App（用网页）**。

---

## 三、五条路线对比

| # | 路线 | UI | 登录 | 4K | 需要 root | 工作量 | 风险 |
|---|---|---|---|---|---|---|---|
| 1 | **LSPosed 模块**（官方 APK + 运行时 hook） | ✅ 原生 | ✅ 正常 | ✅ 可强制 | ✅ 需 | 中（1–2 天） | 低（进程内 hook，不改包） |
| 2 | **Frida 脚本**（同上，不编译模块） | ✅ 原生 | ✅ 正常 | ✅ 可强制 | ✅ 需 | 低（几小时） | 低–中 |
| 3 | **改包 + 迁移官方账号数据**（root 拷贝数据目录） | ✅ 原生 | ⚠️ 绕过登录流程 | ✅ 有补丁 | ✅ 需 | 中 | **中高**（带签名的账号请求可能被风控） |
| 4 | **手机网页版 + 注入**（浏览器/WebView 套壳跑 `m.douyin.com`） | ⚠️ 网页版 | ✅ 网页登录 | ⚠️ 看是否给 4K | ❌ 不需要 | 中 | 低 |
| 5 | 现有改包版 | ✅ 原生 | ❌ 版本过低 | ✅ 有补丁 | ❌ 不需要 | 已完成 | — |

> 注：4 号的可行性取决于手机网页版登录后是否提供 2160P。我们逆出的网页清晰度逻辑（`gearType:-2 = 超清4K`、AB `auto_clarity_reselect`）**手机网页版同样适用**，所以第 2 层机制（AB 改写）可以直接复用。

---

## 四、各路线具体做法

### 路线 1 / 2：root + 运行时 hook（推荐）

**前提**：K40 解 BL 锁 → 刷 Magisk → 装 LSPosed（root 会清数据）。

**hook 点**（已在 APK 里定位，均在 `classes2.dex`）：

```java
// 1) 全局质量模式：设置页"画质调节"就是调它
com.ss.android.ugc.aweme.simkit.ISimKitService.setBitrateQuality(int)

// 2) "手动选择后不再自动调整"（等价于电脑端最关键的那个开关）
com.ss.android.ugc.aweme.playerkit.exp.PlayerSettingCenter.G4()   // 读 not_adjust_after_manually

// 3) 手动清晰度枚举：4K = 9
X.0FWR.Manual_Extremely_High(9, "2160p")
```

LSPosed 骨架（Java）：

```java
public void handleLoadPackage(LoadPackageParam lpparam) {
  if (!"com.ss.android.ugc.aweme".equals(lpparam.packageName)) return;

  // A. 让 not_adjust_after_manually 恒为 true
  XposedHelpers.findAndHookMethod(
      "com.ss.android.ugc.aweme.playerkit.exp.PlayerSettingCenter", lpparam.classLoader,
      "G4", new XC_MethodReplacement() {
        @Override protected Object replaceHookedMethod(MethodHookParam p) { return true; }
      });

  // B. 全局质量模式钉到最高
  XposedHelpers.findAndHookMethod(
      "com.ss.android.ugc.aweme.simkit.SimKitService", lpparam.classLoader,
      "setBitrateQuality", int.class, new XC_MethodHook() {
        @Override protected void beforeHookedMethod(MethodHookParam p) { p.args[0] = 3; }
      });
}
```

Frida 等价（不用编译，`frida -U -f com.ss.android.ugc.aweme -l hook.js`）：

```js
Java.perform(() => {
  const PSC = Java.use('com.ss.android.ugc.aweme.playerkit.exp.PlayerSettingCenter');
  PSC.G4.implementation = function () { return true; };
  const SKS = Java.use('com.ss.android.ugc.aweme.simkit.SimKitService');
  SKS.setBitrateQuality.implementation = function (i) { return this.setBitrateQuality(3); };
});
```

**为什么这条最干净**：APK 一个字节没改，签名没变 → 登录、风控、推送、支付全都正常；
hook 只影响进程内行为，和电脑端"改 AB 响应"的效果等价。

---

### 路线 3：改包 + 迁移官方账号数据（若坚持不 root 的替代方案）

思路：不用登录接口（因此不触发版本校验），而是把**官方 App 已登录的账号数据**搬到改包版里。

1. 先在官方版登录；
2. root 下备份数据目录：
   ```bash
   adb shell su -c "tar -czf /sdcard/dy_acct.tgz -C /data/data/com.ss.android.ugc.aweme ."
   ```
   关键子目录：`shared_prefs/`、`databases/`（账号库）、`files/keva/`、`app_webview/Cookies`
3. 卸载官方版 → 装改包版（同包名）→ 用 root 把数据解回去，并按 uid 修正属主：
   ```bash
   adb shell su -c "chown -R $(stat -c %u /data/data/com.ss.android.ugc.aweme) /data/data/com.ss.android.ugc.aweme"
   ```
4. 启动：通常能直接是已登录状态。

**风险**：账号态生效后，带签名的鉴权请求会暴露"客户端指纹与签名不符"，可能触发二次验证/限流/风控。**不建议长期用**。

---

### 路线 4：手机网页版 + 注入（不 root，最接近"电脑端那套"）

思路：手机端不装 App，用 Chromium 内核浏览器（Kiwi 支持扩展）或自建 WebView 壳加载 `m.douyin.com`，
把我们电脑端的脚本（**几乎可以原样复用**）注入进去：

1. 网页登录（无 APK 签名问题）→ 登录不会被判"版本过低"；
2. 注入 `MANUAL_SWITCH` 写入 + AB 响应改写（`/aweme/v1/web/mobile/ab/params/`、`/service/2/abtest_config/`）；
3. 若手机网页版提供 2160P（取决于该视频与账号），就能固定 4K。

优点：**不需要 root、不需要改包、登录正常**。
缺点：UI 是网页版，不如 App 顺手；手势/预加载/后台播放等体验差一截。

> 这一条是"用手机 UI + 电脑底层"最贴近的实现——只不过"UI"是手机**网页**，不是原生 App。

---

## 五、推荐顺序

1. **想要原生 UI 且能接受 root** → 路线 1（LSPosed）或 2（Frida），1–2 天能出可用结果；
2. **不想 root** → 路线 4（手机网页版 + 注入），可以直接复用现有 JS；
3. **路线 3** 只适合"就是想试试"，不作为长期方案；
4. 现有的改包版（路线 5）留着当"未登录可看的 4K 播放器"也还行——毕竟它播视频是正常 4K 的。

---

## 六、一句话回答你的问题

> **"界面全用手机的、底层用电脑那套"——不存在。**
> 电脑那套之所以成立，是因为它的界面本身就是网页；手机 App 的界面是原生的，底层换不了。
>
> 但你要的**效果**（原生界面 + 4K 固定 + 登录正常）是能实现的，代价是 **root**（路线 1/2）。
> 不想 root 就只能退一步：**手机网页版 + 同一套注入脚本**（路线 4），登录和 4K 都可能保住，但界面是网页的。
