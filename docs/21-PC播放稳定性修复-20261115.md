## 找到的具体原因

- 旧插件即使关闭 FIGHT，仍有补档和尺寸纠偏分支调用硬换源。该路径执行 pause、设置 src、load、play，丢弃现有缓冲；轮询和播放事件又可能重复触发。
- 旧插件改写 AB 配置并设置 needAutoBitrate=false，阻止部分自动选档和卡顿恢复行为，高码率无法及时下载时容易长等。
- 换源失败的定时回退缺少视频身份和尝试序号保护，旧回调可能影响已经切换的视频；直播 MediaStream 也曾被误当作普通低清视频。
- 原响应观察钩子等待副本读取和 JSON 处理完成后才把响应交给应用，重复读取与不设上限的缓存增加额外工作。

旧日志存在约每 6 秒 FAILED 后 restore 的循环。以上机制能解释症状；没有在同一视频、同一网络下完成旧版和新版的受控耗时对照，因此不能计算改善百分比。

## 本次改动

- 在原有脚本中加入并完整序列化 SAFE_PLAYBACK=true，保留 UI 和诊断结构；两个安装器强制使用安全播放模式和 AB_PATCH=false。
- 自动轮询在修改播放器之前返回；停用硬换源、补档抢档、降档拦截、编码能力改判和强制改写标签。旧强制换源诊断入口也返回 disabled。
- 不设置 src、srcObject、播放进度，不主动 pause/load/play，不再由插件关闭原生 ABR 或改写服务端 AB 参数；直播预览保留原生播放链。
- 保留 MANUAL_SWITCH 的 4K 偏好。它仍按 400ms 检查并在不同值出现时重写存储，因此用户手动选低档后存储偏好可能被重置；这不是媒体源重置。原生是否实际执行降档仍取决于客户端，不能由本次证据保证。
- 档位采集独立于 AB 改写，fetch 返回原始 promise 和响应；XHR 不改原生响应 getter，按一次完成事件异步采集并处理复用与中止。
- 排除 /aweme/v1/play/ 媒体下载接口，避免将视频副本当作文本读取。相同档位更新而不重复累加；每档位数组最多 128 条、URI 缓存最多 1024 项、视频所有者缓存最多 96 项。仍有 JSON 接口副本读取成本，未量化。
- 安全模式轮询从 800ms 改为 2500ms，取消 playing/metadata/canplay 的密集重复巡检。
- 新增只读 observe 诊断，使用可视区域及 media 与 player 的准确匹配；详情面板不再拿屏外大分辨率冒充当前画质。
- 同步一键安装副本，保留中文 PowerShell 脚本 UTF-8 BOM，更新旧的固定最高画质承诺。
