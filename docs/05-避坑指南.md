# 避坑指南：这个项目踩过的 20 个坑

> 每条格式：**现象 → 原因 → 正确做法**（附可复核的证据）。
> 踩错顺序基本就是本项目的真实历史，照这个顺序走能省掉几天的试错。

---

## A. 方向类（先别急着写代码）

### 1. 别指望用调试端口/DevTools 协议注入

**现象**：`douyin.exe --remote-debugging-port=92258` 启动后，主进程命令行里确实带着这个开关，但 `http://127.0.0.1:92258/json/version` 永远连不上；换成 `--inspect=9339` 同样不开端口。

**原因**：客户端做了加固（移除调试开关 / `EnableNodeCliInspectArguments` 之类）。

**正确做法**：直接判定 CDP 路线不可用，改用 **preload 注入**。

**证据**：
```
ProcessId 39648  CommandLine: "…\douyin.exe" --remote-debugging-port=92258
（92258 从未 listen；Get-NetTCPConnection 里没有该端口）
```

---

### 2. 别想着"改 `app.asar` 就能改播放器"

**现象**：解包 `app.asar` 后（2313 个文件）找不到任何播放器/清晰度逻辑。

**原因**：客户端界面是**远程网页** `https://www.douyin.com/`，播放器代码在 CDN 的 JS chunk 里，根本不在 asar 内；主进程逻辑还被自研序列化打包进 `__META-INF__/Common.Build-*.node`（非明文，14.6 MB）。

**正确做法**：只动 `resources/app.asar.unpacked/preload.js`（Electron 真正的网页 preload）。

---

### 3. 别改客户端本地的 AB 配置库——会被覆盖

**现象**：直接把 `%APPDATA%\douyin\douyin_app_config`（SQLite，`app_config.abconfig`）里的
`auto_clarity_reselect` 等改成 0，改完一切正常；**20 秒后复查，全部回到 1**。

**原因**：那是服务端 AB 配置的**缓存**，每次启动/刷新都会重新拉取覆盖。

**正确做法**：在**渲染层拦截响应**再改（见第 10 条），而不是改库。
`patch-abconfig.mjs` 只作为排查工具（能 `show/apply/revert`），别当解决方案。

---

## B. 定位类（找错了地方会白干一整天）

### 4. 别把"手动清晰度"当成持久化设置

**现象**：重启客户端后清晰度又回到 1080P，以为是没保存。

**原因**：它存在 **sessionStorage** 的 `MANUAL_SWITCH`，而且客户端在根布局 mount 时会**主动删除**：

```js
useEffect(()=>{ C.pC(SessionStorageKeys.manualSwitch); }, [])   // pC = sessionStorage.removeItem
```

**正确做法**：每帧重新写入 + 心跳补写（400ms），并接受"它是会话级状态"这个事实。

---

### 5. 默认上限是 1080P，是白名单写死的

**现象**：不手动切清晰度时，推荐流最高只有 1080P。

**原因**：`as()` 在没有 `userselection` 时走 `white_list + quality_filter` 过滤，而白名单按 CPU 核数分档，**最高档就是 `normal_1080_0`**（32 核也一样）。

**正确做法**：让 `userselection` 恒非空（写入 `MANUAL_SWITCH`），而不是去改白名单。

---

## C. 逐层试错（这几条最花时间）

### 6. 封 HEVC 会把 4K 一起封掉（关键反例）

**现象**：为"固定在 H.264"，把 `MediaSource.isTypeSupported / canPlayType / mediaCapabilities` 里 HEVC/VVC/AV1 全判为不支持 → 那条 4K 视频**最高只剩 1080P**。

**原因**：**该视频的 4K 就是 HEVC 编码的**；封掉 HEVC 等于封掉 4K。

**正确做法**：如果非要做编码改判，只封 VVC（`REFUSE='vvc'`）；但实测它也不能解决掉档（见第 7 条），所以**最终默认 `REFUSE='none'`**。

---

### 7. 降档不走 `player.changeDefinition`，拦 API 没用

**现象**：给播放器的 `changeDefinition` 套了拦截，日志里确实拦下了一次：

```
08:02:15.130  block   blocked downgrade -> 1
08:02:15.211  media.resize 1080x1920        ← 但媒体流还是被换了
08:02:29.450  state   [{"cur":1,"sel":1}]   ← 还把 1080P 写回了 MANUAL_SWITCH
```

**原因**：播放器**内部直接换 `playAddr` / MSE 码流**，不经过那个公开方法；并且把降档当成"用户选择"写回存储。

**正确做法**：不要在这个层面纠缠，去关掉"决定降档的开关"（第 10 条）。

---

### 8. "把 4K 项塞回列表"会造成拉锯重载

**现象**：`FIGHT` 模式（抽走 4K 项就塞回去 + 切回 4K）下，日志每 ~10 秒一轮：

```
reinject 列表丢了 4K → 塞回 (#1)
revert   cur=1 -> -2 (#1)
reinject (#2) … revert (#2) …
```

用户观感：画面每隔十秒闪一下。

**原因**：客户端每 8~20 秒重建一次档位列表，我们塞回去就触发一次换流，形成军备竞赛。

**正确做法**：默认 `FIGHT=false`（不抢）。真正该做的是让客户端**不再想降档**。

---

### 9. 手写的"合成值"可能和客户端字段对不上

**现象**：自己拼 `{done:1,gearType:-2,gearClarity:"20",gearName:"超清 4K",qualityType:1}` 写进去，某些情况下表现异常。

**原因**：客户端的 `MANUAL_SWITCH` 里还有 `qualityType`、`clarityReal` 等字段，`qualityType` 是**按视频的挡位算出来的**，硬编码不一定对。

**正确做法**：先钩主世界的 `Storage.prototype.setItem`，把客户端自己写过的值存成模板（`__DYPC4K_RAW__`），再用模板 + 只覆盖 `gearType/gearClarity/gearName`。

---

### 10. 【最重要】AB 改写不能贪，多改两个键就掉画质

**现象**：AB 改写生效后 4K 稳定了；但后来把 `use_h266_client`、`fix_h266_list`、`degradeBitrateFactors=[0,0]` 也一起改了 → **部分视频菜单里只剩 720P / 540P**。

**原因**：
- `use_h266_client=0` / `fix_h266_list=0` 会让客户端对服务端"自称不支持 H.266"，部分视频因此拿不到高码流；
- `degradeBitrateFactors=[0,0]` 把降档阈值设成 0，会让降档算法退化到最低档。

**正确做法**：**只改这 5 个键**——

```js
['auto_clarity_reselect', 'switch_clarity_timing', 'smooth_switch_clarity']  // 置 0
'maxDownSwitchLevel' → 0
'rebufferDegrade' / 'safeRebufferDegrade' → 0
```

改完日志会打印命中的键名，便于确认：

```
abpatch xhr .../service/2/abtest_config/ changed=1
        [maxDownSwitchLevel,rebufferDegrade,auto_clarity_reselect,smooth_switch_clarity,switch_clarity_timing]
```

## D. 注入技术类

### 11. preload 在隔离世界，碰不到页面的 `Storage.prototype`

**现象**：在 preload 里 patch `Storage.prototype.setItem`，页面的写入完全看不到。

**原因**：`contextIsolation=true`，preload 与页面是两个 JS 世界（同一个 DOM 与同一个存储后端，但原型链独立）。

**正确做法**：用 `require('electron').webFrame.executeJavaScript(code)` 把钩子装进**主世界**（客户端自己的 preload 也用这招派发 JSBridge 事件）。注意：主世界的钩子看不到 preload 发起的写入——所以"写入"用 preload，"观察"用主世界，两者分工。

---

### 12. 隔离世界里 `sessionStorage` 在 `about:blank` 会抛异常

**现象**：启动初期某些帧报 `Failed to read the 'sessionStorage' property … Access is denied`。

**正确做法**：所有存储访问都包 `try/catch`，并加域名白名单（只处理 `*.douyin.com`）。

---

### 13. 心跳别写成"无脑覆盖"

**现象**：如果你每 400ms 无条件写 `gearType:-2`，用户手动切 1080P 会被立刻改回去（体验很怪）。

**正确做法**：只在"键缺失"或"被改成 auto(0)"时补写；判断依据是现值的 `gearType/gearClarity`。

---

## E. 工程/环境类

### 14. 右键菜单定位不能用"位置/末尾元素"启发式

**现象**：第一版按 `position:fixed` + 扫 DOM 末尾 400 个 div + 正则匹配，**菜单里根本没出现我们的项**。

**原因**：菜单容器未必 fixed，DOM 位置不固定，React 还在异步渲染。

**正确做法**：**按菜单文字特征打分**（命中 ≥3 个已知条目 + 尺寸合理），再往"最小子容器"收一层；并且在 `contextmenu` 后重试 10 次 × 40ms；同时提供 `Alt+I` 兜底。

---

### 15. PowerShell 5.1 读不带 BOM 的 .ps1 会乱码到语法错误

**现象**：`install-preload.ps1` 里中文注释导致 `Missing expression after ','`。

**原因**：Windows PowerShell 5.1 按 ANSI 解析无 BOM 的 .ps1。

**正确做法**：**给 .ps1 写 UTF-8 BOM**（`New-Object System.Text.UTF8Encoding($true)`）；而 JS 片段要写**无 BOM**的 UTF-8。

---

### 16. Node 在 `F:\ddddddd` 下会报 `ERR_INVALID_PACKAGE_CONFIG`

**现象**：任何 `node xxx.js` 都报 `Invalid package config \\?\F:\ddddddd\package.json`。

**原因**：上级目录有个 **0 字节的 `package.json`**，Node 向上查找时解析失败。

**正确做法**：在工作目录放一个合法的最小 `package.json`：

```json
{"name":"work","version":"1.0.0","private":true,"type":"commonjs"}
```

---

### 17. 安装/卸载必须检查进程占用与幂等

**现象**：客户端运行时写入 `preload.js`，重启后行为不确定；重复安装导致补丁块叠加。

**正确做法**：
- 安装脚本先 `Get-Process douyin, douyin_tray` 检测，运行中直接报错退出（或显式 `-AllowRunning`）；
- 写入前用正则剥掉旧补丁块（`/\* ==== dypc4k begin ==== \*/ … end ==== \*/`），保证幂等；
- 只备份一次，永远保留官方原始文件。

---

## F. 安卓端专属（如果你以后还要试）

### 18. 包名不要做"字节级全局替换"

**现象**：把 manifest 里 `com.ss.android.ugc.aweme` 全部替换成新包名（1051 处）→ 装上了但**启动即崩**：

```
ClassNotFoundException: Didn't find class "com.dypc4k.douyin.client.app.host.AwemeHostApplication"
```

**原因**：连**类名**一起改了，而 dex 里的类名没变。

**正确做法**：只改三类字符串——`package` 属性值、`provider authority`、`自定义权限`；**类名一律不动**（解析二进制 manifest 的字符串池，按解码后的字符串精确匹配）。

---

### 19. 改包名必须同时处理 authority，否则装不上

**现象**：`INSTALL_FAILED_CONFLICTING_PROVIDER: provider name com.ss.android.ugc.aweme.gkfs … already used`。

**原因**：Android 安装时校验 provider authority 唯一性；有些 authority **不含包名前缀**（`IntelligentIntent`、`SHARE_PROVIDER_AUTHORITY1128`、`com.bytedance.ies.wallpapercaller`），不会跟着改名。

**正确做法**：把所有 authority（含不带前缀的）都做**等长替换**，并同步改 dex 里引用它们的字符串。

---

### 20. 同包名 + 自定义签名，登录仍会被风控拒

**现象**：改成官方包名、只打一处 smali 补丁，能装能刷能播；但输完验证码提示 **「当前版本过低」**，点升级无反应。

**原因**：登录时客户端上报 `metasec` 生成的设备/客户端指纹，服务端发现签名与已知客户端不符 → 判定版本异常。**这个判定在服务端**。

**正确做法**：不要试图在客户端绕（要么伪造整套指纹/对抗风控，随时失效）。想要"官方版 + 画质改造"，唯一正路是 **root + LSPosed/Frida 运行时 hook**，保持原包原签名。

---

## 附：一句话总结

> 改不动的地方就别硬改；**找到那个真正做决定的开关**（本例是服务端 AB 里的 `auto_clarity_reselect`），
> 在它到达客户端之前改掉，比在结果上反复拦截划算一个数量级。
